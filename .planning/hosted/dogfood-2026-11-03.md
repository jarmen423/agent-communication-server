## Blockers: a founder can't get through these without help

- **B1. `acs worker run claude|codex` fails from a release install.**
  - `acs` looks for `<backend>_worker.py` in the worker bundle.
  - The bundle (`packaging/remote/FILES.txt`) ships only
    `remote_agent_adapter.py` with the shell, kilo and opencode backends.
    There is no `claude_worker.py`, `codex_worker.py`, `claude_code.py` or
    `codex_cli.py`.
  - The hosted e2e tests passed only because they used a checkout.
  - Fix: either ship the worker entrypoints and backends in the bundle,
    or have `acs` embed them the way it already embeds the MCP modules
    (preferred, because it's one install).
- **B2. `acs` is not on PATH after install.**
  - The binaries land in `~/.local/share/nats-hub/bin`, with no symlink
    into `~/.local/bin` and no PATH hint.
  - Fix: symlink into `~/.local/bin` (create it if missing) and print a
    PATH line if it isn't on PATH.
- **B3. `acs login` defaults to `http://127.0.0.1:9300` (the dev stub).**
  - Fix: default release builds to `https://acs.agentmemorylabs.com`.
  - Keep `--server`/`ACS_SERVER` for self-host and dev.
- **B4. Nothing tells a hosted user what to do.**
  - The installer's closing message describes the old self-host token
    flow (`NATS_TOKEN`, `hub-delegate-remote`) and never mentions
    `acs login`.
  - The README has no hosted quick start (section D is local DEV ONLY).
  - Fix: a hosted quick start in the README, and an installer message
    that ends with `acs login`.
- **B5. There is no Windows build.**
  - Windows users can only use the claude.ai/ChatGPT connector, or WSL
    (untested).
  - Decide: a Windows build, or a documented WSL path.

## Friction

- **F1. The worker bundle installer doesn't match `acs`.**
  - It defaults to `~/nats-hub-remote`, while `acs worker run` looks in
    `~/.local/share/nats-hub/remote`.
  - Its closing message points at `remote_agent_adapter.py --backend
    kilo`.
  - It's a second installer, and the first one never mentions it. B1's
    preferred fix removes it from the hosted path.
- **F2. The `hub-*` CLIs and `acs` identities don't fit together.**
  - No `NATS_URL` env support: the flag is the only way, and the default
    is `nats://127.0.0.1:4222`. On a machine with a local nats-server,
    that gives a confusing "authorization violation".
  - The identity comes from `--from` on `hub-delegate` but from
    `NATS_HUB_IDENTITY` on `hub-agents`.
  - The user has to find the creds file under `~/.config/acs/creds/` by
    hand.
  - An unset identity gives a generic "deadline has elapsed" timeout on
    a bound-identity hub.
  - Fix: `acs exec <identity> -- <cmd>` (or `acs env <identity>`), which
    sets `NATS_URL`, `NATS_CREDENTIALS_FILE` and `NATS_HUB_IDENTITY`.
    Make every CLI read `NATS_URL` and `NATS_HUB_IDENTITY` as defaults.
    Name the identity problem in the timeout error.
- **F3. `acs status` prints credential expiry as a raw epoch.**
- **F4. MCP `delegate_task`: Claude passed a wrong argument name on its
  first call.** The validation error should list the valid arguments
  (`to`, `prompt`, `timeout`).
- **F5. `acs agent add` has no `--provider` flag.** Identity decision #6
  in `OPEN_DECISIONS.md` is still a proposal.

- **F6. The connector shows the Agent Memory Labs icon, not the ACS mark.**
  `acs.agentmemorylabs.com/favicon.ico` is a 404, so claude.ai falls back
  to the parent domain's favicon. Fix (acs-private): serve the `brand/`
  mark as `/favicon.ico` and `/icon.svg`, with `<link rel="icon">` on the
  sign-in and consent pages.
  - **Fixed 2026-11-03** in acs-private `896fd90`. Only the `acs-cp`
    container was redeployed; the rollback image is
    `acs-beta-cp:pre-icon-2026-11-03`. claude.ai may show the cached old
    icon for a while.
- **F7. Only claude.ai and ChatGPT can sign in to the remote MCP.**
  - The redirect allowlist (`acs-private`
    `crates/server/src/oauth/redirects.rs`) holds only the claude.ai,
    claude.com and chatgpt.com callbacks. Production sets no
    `ACS_OAUTH_EXTRA_REDIRECT_URIS` and leaves loopback redirects off.
  - Grok already has an identity prefix (`grok-web`), but its callback
    URL isn't documented, so it isn't allowlisted. To find it, add the
    connector in Grok and read the refused URI. Then add it through
    `ACS_OAUTH_EXTRA_REDIRECT_URIS`, which needs a config change and a
    restart but no rebuild.
  - Clients that take only a URL plus a static bearer header can't
    connect, because there is no personal-access-token path.

## Ops

- **O1. Folder collision on the server.** Operator secrets live in
  `~/.config/acs` on acs-dev, which is also the client's default
  `ACS_HOME`. Today's worker used `ACS_HOME=~/.local/share/acs-worker` to
  stay clear. Move the operator secrets to `~/.config/acs-operator`
  (acs-private: `beta_up.sh`, watchdog, backups).
